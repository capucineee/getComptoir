Connecteur personnalisé

Envoyer vos commandes vers Comptoir

Ce guide s'adresse au développeur ou à la développeuse qui gère le site marchand. Il explique comment brancher son backend pour que chaque nouvelle commande apparaisse automatiquement dans Comptoir, en temps réel.

1

Créer le connecteur dans Comptoir

Dans l'onglet Connecteurs de l'app → + Connecteur personnalisé → donner un nom (ex. le nom du site).

2

Récupérer la clé API et l'endpoint

Comptoir affiche immédiatement une clé API unique et l'adresse à appeler. Transmettre ces deux informations au développeur — la clé ne sera plus réaffichée ensuite.

3

Appeler l'endpoint à chaque commande

Repérer, dans le code du site, l'endroit où une commande est finalisée (fin de paiement, webhook Stripe, etc.) et y ajouter un appel HTTP vers Comptoir.

01Requête

Un POST avec la clé API en en-tête Authorization. Seul le montant est obligatoire — tout le reste est optionnel.

Endpoint
POST /api/ingest/orders
Exemple — curl
curl -X POST /api/ingest/orders \
  -H "Authorization: Bearer VOTRE_CLÉ_API" \
  -H "Content-Type: application/json" \
  -d '{
    "externalId": "CMD-1234",
    "amount": 42.90,
    "status": "livree",
    "customerName": "Jeanne Dupont",
    "productName": "Étole en lin écru"
  }'
Exemple — JavaScript (fetch)
await fetch("/api/ingest/orders", {
  method: "POST",
  headers: {
    "Authorization": "Bearer VOTRE_CLÉ_API",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    externalId: "CMD-1234",
    amount: 42.90,
    status: "livree",
    customerName: "Jeanne Dupont",
    productName: "Étole en lin écru"
  })
});
Anti-doublon. Si externalId est fourni et qu'une commande avec le même identifiant existe déjà, l'appel est ignoré sans créer de doublon — il peut donc être renvoyé sans risque en cas d'échec réseau.

02Champs reconnus

Comptoir détecte automatiquement plusieurs noms de champs courants, insensible à la casse — pas besoin de reformater exactement les données du site pour qu'elles correspondent.

Champ ComptoirAlias reconnus
amountrequistotal, montant, price, totalPrice, grandTotal — tolère virgule décimale et symbole €
statusoptionnelstatut, state, orderStatus — voir statuts ci-dessous ; à défaut, déduit de signaux comme shipped_at, cancelled_at, fulfillment_status
externalIdrecommandéorderId, order_id, reference, ref, orderNumber
dateoptionnelcreated_at, createdAt, order_date — format ISO 8601, défaut : maintenant
customerNameoptionnelclient, clientName, nom_client, ou objet customer: {name}
productNameoptionnelproduct, article, item, ou premier élément d'un tableau items/products

03Statuts acceptés

Trois statuts existent côté Comptoir. Les valeurs suivantes sont reconnues automatiquement, avec ou sans accents.

livree
delivered, shipped, completed, fulfilled, paid, payee
preparation
pending, processing, en_attente, created, new, confirmed (défaut)
retour
refunded, returned, cancelled, canceled, annulee, rembourse
Un statut non reconnu ne bloque pas l'envoi : la commande est acceptée avec le statut preparation, et la réponse inclut un champ note le précisant.
